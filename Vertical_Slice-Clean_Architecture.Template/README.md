# Vertical_Slice-Clean_Architecture.Template

A .NET 10 `dotnet new` template that combines Vertical Slice Architecture with Clean Architecture
layering. Each feature is a self-contained slice: its request, response, validator, handler and
endpoint live together in one file under `Features/`. The domain model and the infrastructure
(persistence, health checks, correlation IDs, versioning) stay in their own projects.

When a solution is created you choose its data access (**EF Core** or **Dapper**) and database
engine (**SQL Server**, **PostgreSQL** or **MySQL**). This reference is generated from the template's
default combination, EF Core on SQL Server; the Dapper connection factories appear only in solutions
created with Dapper.

## How a slice works

1. A static class per use case (for example `GetSample`, `PostSample`) nests the slice's
   `Query`/`Command`, `Response`, optional FluentValidation `Validator`, `Handler` and `Endpoint`.
   Requests and responses are the slice's own types; domain entities never reach the HTTP contract.
2. `AddSlices` scans the API assembly and registers every `ISliceHandler`, every `IEndpoint`, and every validator.
3. `MapSlices` asks each `IEndpoint` to map its own Minimal API route, inside one route group shared by all slices.
4. `WithValidation<TRequest>()` runs the request's validator before the handler and returns a
   `400` validation problem response on failure.
5. Errors are RFC 9457 `ProblemDetails` responses, built through the `Problems` helpers, and every
   one carries the request's `correlationId`.
6. Reads go through the query side (`QueryDbContext`, no tracking) and writes through the command
   side (`CommandDbContext`), which can point at different databases.
